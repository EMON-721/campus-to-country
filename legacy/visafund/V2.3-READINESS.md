## Security findings and configuration gates

Production environment-variable inventory is empty. Email/password and administrator MFA remain securely disabled until actual Supabase configuration. AUTH-INTEGRATION.md gives exact variables, redirect URLs, token-hash email templates and trusted administrator linking process. Required: SUPABASE_URL, modern SUPABASE_PUBLISHABLE_KEY, APP_ORIGIN, AUTH_PROVIDER_ENABLED after staging checks, actual verified Site-scoped SUPER_ADMIN_USER_IDS and approved deletion retention policy. Configure real SMTP/domain verification, email confirmation, signing/session controls and TOTP. Never send secret keys in chat. No service-role key is needed by this auth adapter.

Admin suspension blocks application access immediately through status checks. Revoking another user's provider session/deleting the provider identity remains a separate unimplemented privileged integration. Account deletion follows the existing confirmation/retention job process; D1 and R2 cleanup is not atomic and needs operational retry/restore testing. Generic country/content management persists metadata/drafts; not all generic published content is dynamically wired into the active directory. Verified requirement publication still uses immutable rules.

Ownership and role enforcement are server-side and regression-tested. D1 is accessed only by the Worker, not a public client SQL API; this is not a claim of PostgreSQL RLS. R2 downloads require owner identity and return attachments/no-store/nosniff. XSS protection includes escaped React output, CSV formula escaping, attachment downloads and baseline CSP; CSP still permits unsafe-inline and is not a strict nonce-based policy. Upload signature validation does not replace antivirus/CDR scanning.

Hosting/infrastructure operators retain privileged database, file-storage, code-deployment and environment access. VisaFund is not zero knowledge or end-to-end encrypted. HTTPS and Secure cookies are configured; provider-managed encryption at rest, key custody, operator controls and backup guarantees require infrastructure verification. No claim is made that these were independently audited.

Current dependency audit remains NONZERO: 1 high braces stack-exhaustion advisory (no patched version reported) and 1 moderate legacy esbuild under drizzle-kit. They remain development tooling risks; no suppression or clean-audit claim. Do not expose development servers. Compatibility-reviewed dependency remediation and independent security review remain release gates.

A source archive is not a D1/R2 backup. No supported production database/file export-and-restore workflow was available. No backup/restore test, production migration, auth credential change, runtime environment update or public access change was performed.
